# 집길 스크롤 지도 진입·실거래 연결 설계

> 상태: 사용자 승인 완료
>
> 작성일: 2026-08-09
>
> 대상 저장소: `real-estate-sv`
>
> 상위 설계: `2026-08-08-housing-navigation-platform-design.md`, `2026-08-08-housing-entry-map-redesign.md`

## 1. 목적

첫 화면의 지도를 장식이 아니라 서비스 탐색의 시작점으로 바꾼다. 사용자가 직접 요청한 현재 위치 또는 서울을 기준으로 지도가 전국에서 읍면동까지 단계적으로 확대되고, 마지막 장면에서 주거 찾기와 실거래 지도로 진입한다.

이번 변경은 다음 문제를 함께 해결한다.

1. 현재 첫 화면에서 지도와 두 기능이 연결되어 보이지 않는다.
2. 실거래 진입 후 지도가 남고 기존 분석 화면은 아래에 떨어져 있어 기능이 없는 것처럼 느껴진다.
3. 데스크톱 주거 질문창이 오른쪽으로 치우쳐 있다.
4. 다음 질문으로 이동할 때 제목에 붉은 사각형 포커스가 나타났다가 터치하면 사라진다.
5. 질문 완료 후 창이 닫혀 저장된 조건과 다음 행동을 확인하기 어렵다.
6. 국내 사용자에게 익숙한 한국어 지도를 사용하고 싶다.

## 2. 이번 구현 범위

### 포함

- 카카오맵 기반 고정 지도와 스크롤 장면 전환
- 사용자 동작으로 요청하는 현재 위치 권한
- 위치 권한 거부·실패 시 서울 시작
- 전국, 시도, 시군구, 읍면동의 4개 확대 장면
- 마지막 장면의 주거 찾기·실거래 지도 진입
- 데스크톱 중앙 질문창과 모바일 하단 시트
- 포인터 입력 후 질문 제목에 나타나는 사각 포커스 표시 수정
- 질문 완료 후 핵심 선택값 칩으로 축소
- 선택값 칩을 누른 단일 질문 편집
- 현재 지역을 기존 실거래 조회 조건으로 전달
- 실거래 지도와 결과 패널 연결
- 현재 페이지의 실제 거래 주소를 좌표화한 가격 핀
- 기존 거래 상세, 전월세, 기간 분석, 비교 분석 연결
- 카카오맵 실패 시 기존 OpenFreeMap과 수동 지역 선택 사용

### 제외

- 임대주택 모집공고 수집과 정규화
- 임대주택·주거비 지원 자격 판정
- 공식 공고 맞춤 결과와 예상 월 부담 결과
- 회원가입과 서버의 사용자 조건 저장
- 모든 거래를 사전 좌표화하는 D1 배치 작업
- 카카오맵 무료 쿼터를 넘는 유료 사용 자동 활성화
- 푸시, 배포, 운영 환경변수 변경

임대공고 맞춤 결과는 승인된 상위 플랫폼 설계의 다음 구현 단계로 유지한다. 이번 단계의 주거 찾기는 질문, 로컬 저장, 축소 요약, 개별 수정, 실거래 교차 이동까지 완성한다.

## 3. 승인된 화면 흐름

### 3.1 첫 장면

- 카카오맵은 화면 전체에 고정한다.
- 지도 위에는 서비스 제목과 `내 주변에서 시작` 버튼을 표시한다.
- 위치 권한은 페이지 로드나 첫 스크롤에서 자동 요청하지 않는다.
- 사용자가 `내 주변에서 시작`을 누른 경우에만 브라우저 위치 권한을 요청한다.
- 위치 권한을 거부하거나 위치 확인이 실패·시간 초과하면 서울 중심으로 전환하고 `서울에서 시작합니다` 상태를 표시한다.
- 사용자는 언제든 지역·단지·주소 검색으로 시작 위치를 변경할 수 있다.

### 3.2 스크롤 확대

지도는 화면에 고정하고 설명 장면만 스크롤한다. 스크롤 양과 지도 배율을 1대1로 묶지 않고 장면 경계를 통과할 때 카메라를 이동한다.

1. 전국
2. 현재 위치의 시도
3. 현재 위치의 시군구
4. 현재 위치의 읍면동

위치 권한이 없으면 `대한민국 → 수도권 → 서울 → 서울 중심 지역`으로 이동한다. 사용자에게 특정 구나 동을 실제 현재 위치처럼 표현하지 않는다.

첫 세 장면에서는 마우스 휠을 페이지 스크롤에 사용하고 지도 휠 확대는 비활성화한다. 마지막 장면에 도착하면 지도 이동·확대·축소를 활성화한다. `소개 건너뛰기`를 제공해 마지막 장면으로 바로 이동할 수 있게 한다.

### 3.3 마지막 장면

지도 아래에 같은 비중의 두 진입 버튼을 표시한다.

- `내게 맞는 주거 찾기`
- `지도에서 실거래 찾기`

현재 위치에서 얻은 지역 상태를 두 경로가 공유한다. 경로를 전환해도 지도 중심과 선택 지역을 잃지 않는다.

## 4. 위치와 지역 상태

### 4.1 현재 위치

브라우저의 위치 API는 사용자 버튼 클릭 후 한 번만 호출한다. 성공한 좌표는 카카오 지도 서비스의 `coord2RegionCode`로 법정동과 지역 코드로 변환한다.

정확한 위도·경도는 화면의 현재 세션에서 지도 이동에만 사용한다. 로컬 저장소나 프로젝트 서버에는 원본 좌표를 저장하지 않는다. 저장값은 변환된 지역 코드와 표시 이름으로 제한한다.

지역 코드 변환 과정에서는 좌표가 카카오 지도 서비스로 전달된다. 위치 사용 안내에 이 사실과 프로젝트 서버가 정확한 좌표를 저장하지 않는다는 점을 함께 표시한다.

### 4.2 거부·오류

다음 상태는 모두 서울 시작으로 통합한다.

- 권한 거부
- 위치 API 미지원
- 위치 확인 시간 초과
- 좌표 확인 실패
- 좌표의 지역 코드 변환 실패

오류 상세를 기술 용어로 노출하지 않는다. `현재 위치를 확인하지 못해 서울에서 시작합니다`와 `지역 변경`을 제공한다.

### 4.3 수동 지역 변경

지역·단지·주소 검색은 카카오 지도 검색을 사용한다. 검색 결과를 선택하면 지도 중심, 지역 코드, 주거 선호 지역, 실거래 검색 조건을 같은 상태로 갱신한다.

## 5. 지도 공급자와 설정

### 5.1 기본 공급자

기본 지도는 카카오 지도 Web JavaScript SDK를 사용한다. 다음 라이브러리를 함께 로드한다.

- `services`: 좌표→지역 코드와 주소→좌표 변환

이번 범위는 최대 20개 핀만 표시하므로 별도 군집 라이브러리는 사용하지 않는다.

### 5.2 키 관리

카카오 JavaScript 키의 실제 값은 소스, 문서, 테스트 fixture, 로그에 기록하지 않는다. Cloudflare 환경값으로 보관하고 동일 출처의 `GET /api/map-config` 응답을 통해 지도 로더에 전달한다. 응답은 지도 공급자와 브라우저에서 사용해야 하는 JavaScript 키만 포함한다.

카카오 개발자 콘솔에는 다음 허용 도메인만 등록한다.

- 운영 Worker 도메인
- 사용자가 승인한 정식 도메인
- 로컬 개발에 필요한 localhost 주소

클라이언트용 JavaScript 키는 브라우저 전달이 필요한 값이므로 도메인 제한을 필수 보호수단으로 사용한다. 유료 API 사용은 자동으로 켜지 않는다.

### 5.3 실패 대체

다음 경우 기존 OpenFreeMap을 표시한다.

- 런타임 지도 설정이 없음
- 카카오 SDK 로드 실패
- 카카오 지도 생성 실패

대체 상태에서는 기존 실거래 조회와 수동 시도·시군구·읍면동 선택을 계속 사용할 수 있다. 주소 좌표화가 불가능하면 가격 핀을 만들지 않고 실제 거래 목록만 표시한다. 화면에는 `기본 지도로 표시 중`을 알린다.

## 6. 주거 질문과 축소 요약

### 6.1 질문창

- 데스크톱: 화면의 가로·세로 정중앙, 최대 너비 520px
- 모바일: 지도 상단이 보이는 하단 시트
- 한 화면에 질문 하나만 표시
- 이전, 다음, 닫기와 진행 상태 유지
- 지도와 질문창이 동시에 화면 밖으로 밀리지 않게 한다.

### 6.2 포커스 표시

현재 붉은 사각형은 다음 질문을 렌더링한 후 제목에 프로그램으로 포커스를 옮기고 `:focus` 스타일을 적용해 발생한다.

- 포인터·터치 입력 뒤에는 제목 외곽선을 표시하지 않는다.
- 키보드 입력에는 `:focus-visible` 고대비 외곽선을 유지한다.
- 질문 제목 포커스 이동과 스크린리더 안내는 유지한다.
- 외곽선을 완전히 제거해 접근성을 낮추지 않는다.

### 6.3 질문 완료

마지막 질문의 버튼은 `조건 저장`이다. 저장 후 질문창을 닫아 빈 지도로 돌아가지 않고 지도 아래의 축소 조건 바로 전환한다.

기본 노출 칩은 다음 네 개다.

- 가구 유형
- 무주택 상태
- 정책상 나이 구간
- 희망 지역

소득, 자산, 현재 주거비는 `상세 조건` 칩 안에 묶는다. 칩을 누르면 전체 질문을 다시 시작하지 않고 해당 질문 하나만 작은 편집창으로 연다. 저장 후 편집창은 닫히고 칩 문구가 즉시 갱신된다.

축소 조건 바에는 `이 지역 실거래 보기`를 함께 표시한다. 이 버튼은 희망 지역을 실거래 지도에 전달한다.

## 7. 실거래 지도 연결

### 7.1 화면 구성

모바일은 지도 위 하단 시트, 데스크톱은 지도 우측 패널을 사용한다.

패널에는 다음을 표시한다.

- 현재 지역
- 매매·전세·월세
- 부동산 유형
- 기준 기간
- 현재 조회 건수
- 실제 거래 목록
- 로딩·오류·빈 결과 상태

모바일 하단 시트는 접힘과 펼침의 두 상태를 가진다. 접힌 상태에서는 지도를 계속 조작할 수 있다.

### 7.2 기존 분석 연결

현재 위치 또는 검색 결과의 법정동 코드를 기존 시도·시군구·읍면동 선택값으로 변환한다. 기준 월은 현재 선택값이 있으면 유지하고 없으면 기존 기본 월을 사용한다.

위치 권한을 사용하지 않아 서울로 시작한 경우 서울 시도만 선택하고 임의 시군구 거래를 자동 조회하지 않는다. 사용자가 시군구를 선택하면 기존 규칙대로 구 전체 또는 선택 읍면동을 조회한다.

기존 실거래 호출, 취소 거래 구분, 통계, CSV, 거래 상세, PNU, 건축물, 토지이용, 조례, 비교 분석 로직을 재사용한다. 동일한 API를 지도용으로 다시 만들지 않는다.

### 7.3 실제 가격 핀

현재 거래 응답에는 위도·경도가 없다. 따라서 현재 페이지에 표시된 거래 중 주소가 있는 고유 주소 최대 20개만 카카오 `addressSearch`로 좌표화한다.

- 시도, 시군구, 법정동, 지번 또는 도로명을 조합한 실제 주소 사용
- 같은 주소는 한 번만 요청
- 브라우저 세션 동안 성공·실패 결과 모두 캐시
- 좌표 검색 성공 시에만 가격 핀 생성
- 결과 없음이나 오류는 목록만 유지하고 핀 생략
- 오래된 검색 응답이 새 지도 상태를 덮어쓰지 못하게 요청 세대 확인
- 필터나 페이지가 바뀌면 현재 표시 거래를 기준으로 핀 갱신

핀을 선택하면 동일 주소의 거래 요약을 표시하고, 목록 항목과 같은 기존 거래 상세 패널을 연다. 주소가 불명확한 거래에 임의 좌표나 지역 중심 좌표를 사용하지 않는다.

## 8. 모듈 경계

기존 정적 프런트엔드 구조를 유지하되 책임을 다음처럼 분리한다.

- `entry-map.js`: 카카오·OpenFreeMap 생성, 카메라, 현재 중심, 대체 상태
- 새 스크롤 모듈: 장면 진입 감지, 카메라 단계, 건너뛰기, 동작 줄이기
- `entry-experience.js`: 홈·주거·실거래 모드 전환과 포커스
- `housing-profile.js`: 질문, 저장값, 핵심 칩과 개별 답변 갱신에 필요한 순수 로직
- 새 실거래 지도 모듈: 지역 상태 전달, 결과 패널, 주소 좌표화, 가격 핀
- `main.js`: 기존 조회·통계·상세 기능 유지, 지도 모듈에 현재 결과를 전달하는 최소 연결점만 추가
- Worker 지도 설정 경로: 환경값의 존재 확인과 런타임 지도 설정 제공

지도 공급자 차이를 위한 범용 프레임워크를 만들지 않는다. 현재 필요한 카메라·지역 변환·핀 기능만 명확한 메서드로 노출한다.

## 9. 상태 흐름

```text
내 주변에서 시작
  → 위치 좌표 확인
  → 카카오 좌표→법정동 변환
  → 지도 4개 장면
  → 주거 찾기 또는 실거래 지도

주거 찾기
  → 질문 7개
  → 브라우저 로컬 저장
  → 핵심 조건 칩
  → 칩 하나 편집 또는 이 지역 실거래 보기

실거래 지도
  → 지역 코드로 기존 API 조회
  → 목록·통계 표시
  → 현재 페이지 고유 주소 최대 20개 좌표화
  → 성공한 주소만 가격 핀
  → 핀·목록에서 기존 상세·비교
```

## 10. 성능과 접근성

- 스크롤 이벤트마다 지도 API를 호출하지 않고 장면이 바뀔 때만 카메라 이동
- 장면 진입은 `IntersectionObserver`로 감지하고 같은 장면에서는 카메라 이동을 반복하지 않음
- 주소 좌표화는 고유 주소 최대 20개로 제한
- 같은 주소의 좌표 결과를 세션 캐시
- 새 필터가 적용되면 이전 좌표화 결과의 화면 반영 취소
- `prefers-reduced-motion`에서는 부드러운 카메라 이동 대신 즉시 이동
- 소개 건너뛰기 제공
- 지도만으로 정보를 전달하지 않고 목록을 항상 제공
- 버튼과 칩의 키보드 접근 및 최소 터치 영역 유지
- 상태 변화는 읽을 수 있는 문구와 `aria-live`로 안내
- 데스크톱 1280px 이상과 모바일 390px에서 가로 잘림 금지

## 11. 오류 처리

| 상황 | 사용자 동작 |
|---|---|
| 위치 권한 거부·실패 | 서울 시작, 지역 변경 제공 |
| 카카오 지도 설정 없음 | OpenFreeMap과 기존 지역 선택 유지 |
| 카카오 SDK 오류 | 기본 지도 상태 안내, 실거래 목록은 계속 사용 |
| 좌표→지역 변환 실패 | 서울 시작 또는 수동 지역 검색 |
| 주소→좌표 결과 없음 | 해당 거래 핀만 생략, 목록 유지 |
| 실거래 API 실패 | 기존 오류 안내와 `다시 조회` 제공 |
| 실거래 결과 없음 | 지역·기간·유형 변경 제안 |
| 빠른 필터 전환 | 최신 요청만 화면에 반영 |

## 12. 보안과 개인정보

- 정확한 현재 위치 좌표를 D1, Worker 로그, 로컬 저장소에 저장하지 않는다.
- 브라우저에는 지역 코드와 표시 이름만 저장할 수 있다.
- 카카오 키의 실제 값은 소스·문서·테스트·로그에 남기지 않는다.
- 카카오 JavaScript 키는 허용 도메인을 제한한다.
- 지도 설정 응답에는 필요한 클라이언트 지도 설정 외의 비밀값을 포함하지 않는다.
- 검색어와 지역 코드는 기존 입력 검증 범위 안에서 처리한다.
- 외부 지도 실패가 기존 공식 실거래 API 접근을 막지 않게 한다.

## 13. 검증 기준

### 단위·통합 테스트

- 장면 번호별 지도 확대 수준과 중심 이동
- 위치 성공, 거부, 시간 초과, 미지원의 서울 대체
- 위치 좌표를 프로젝트 서버나 로컬 저장소에 저장하지 않음
- 현재 지역을 기존 시도·시군구·읍면동 조건으로 전달
- 질문 완료 후 핵심 조건 칩 표시
- 칩 하나 수정 후 저장값과 문구 갱신
- 터치 전환에서는 제목 사각 외곽선 없음
- 키보드 전환에서는 `:focus-visible` 확인
- 고유 주소 20개 제한과 중복 제거
- 주소 좌표화 성공·실패 캐시
- 좌표 성공 거래만 핀 생성
- 오래된 조회·좌표 결과 무시
- 카카오 실패 시 OpenFreeMap과 기존 조회 유지

### 브라우저 QA

- 데스크톱 1440px: 고정 지도, 4개 장면, 중앙 질문창, 우측 실거래 패널
- 데스크톱 1280px: 가로 잘림 없음
- 모바일 390px: 하단 질문 시트, 축소 칩, 실거래 하단 시트
- 위치 권한 허용·거부
- 소개 건너뛰기
- 동작 줄이기
- 지도 SDK 실패
- 주소 좌표화 일부 실패
- 키보드만으로 질문, 칩 수정, 실거래 목록·상세 이동
- 가로 스크롤, 화면 밖 잘림, 콘솔 오류 없음

### 회귀

- 매매·전세·월세 조회
- 시도→시군구→기준월→선택 읍면동 또는 구 전체 조회
- 취소 거래 구분
- 평당가와 거래 상세
- 기간 분석과 3개 비교
- PNU·건축물·토지이용·조례 상세
- 전체 테스트, 타입 검사, 프런트 문법 검사, 배포용 빌드

## 14. 완료 조건

- 사용자가 위치 권한 버튼을 눌러 현재 지역으로 스크롤 확대를 시작할 수 있다.
- 위치를 제공하지 않아도 서울에서 전체 흐름을 사용할 수 있다.
- 마지막 장면에서 두 경로가 실제 다음 기능으로 연결된다.
- 주거 질문창이 데스크톱 중앙, 모바일 하단에 표시된다.
- 터치로 다음 질문을 눌렀을 때 붉은 제목 사각형이 나타나지 않는다.
- 질문 완료 후 핵심 조건 칩이 남고 각 항목을 개별 수정할 수 있다.
- 실거래 지도가 현재 지역으로 기존 공식 조회를 실행하고 결과 패널을 표시한다.
- 주소 좌표가 확인된 실제 거래만 가격 핀으로 표시된다.
- 지도·위치·좌표화 실패가 기존 실거래 기능을 차단하지 않는다.
- 기존 실거래 기능 회귀 없이 정의된 검증이 통과한다.
